# Short submission summary

**Where I spent my time.** I spent the first thirty minutes to an hour reading the assignment thoroughly and also doing research regarding existing work that would be helpful for this assignment. Then, I created and iterated on a detailed implementation plan based on my ideas and key decisions. I implemented this plan and spent the rest of the time troubleshooting and expanding more functionality on the workflow. Most of the time after implementation was in making sure the workflow worked as I had expected and to make ensure the quality of the product.

**What I left out.** I used scripted text conversations so the same failure could be replayed. Speech recognition, interruptions during a live call, and integration with a real clinic were outside that scope. The simulation ends when it records a callback or handoff, so the workbench cannot establish whether a person picked it up. I also did not test on all the possible scenarios that could occur so you would have to add new scenarios in order for it to evaluate those capabilities.

**How I used AI tools.** I used a coding assistant to help implement the workbench, run checks, inspect saved traces, and draft the submission materials. I used AI to mainly implement my ideas and also research existing tools and scenarios for reference. 

**What I’d do next.** I tried to implement a LLM as part of the evaluator. I think that would be very beneficial because then the evaluator would be able to handle more unfamiliar text and chat. However, I was limited by budget since there was no opensource api key that had enough tokens to run even one evaluation across the 20 scenarios. So that would be my next step to further improve this pipeline and fill in the biggest gap once given the resources to do so. I think that is the biggest limitation of the current pipeline which is it cannot handle foreign scenarios outside the scripted ones very well.
